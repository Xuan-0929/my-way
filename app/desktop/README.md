# My Way Desktop

本地优先的 macOS 学习日历，使用 Electron、React 和 TypeScript。它只通过受控 Electron 主进程读取或写入用户选择的 `my-way` 文件夹，不包含 Git、GitHub、云同步、AI、通知或账户系统。

正式安装版的渲染会话默认拒绝 HTTP(S) 与 WebSocket 请求，并拒绝相机、麦克风、蓝牙、定位和通知权限；只有开发模式下的精确本机回环地址可用于热更新。打包时会移除未使用的 macOS 隐私用途声明，避免系统误示权限需求。

当前桌面版本：`1.0.0`。

## 环境

- Apple Silicon macOS
- Node.js 20

## 开发

```bash
npm install
npm run dev
```

首次启动时选择包含 `README.md`、`00-dashboard/` 和 `05-admissions/` 的 `my-way` 根目录。

## 验证

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
```

`test:e2e` 会启动真实 Electron，使用临时学习工作区验证首次选择目录、每日与每周文件、日历拖动、任务详情、计时器重启与时长分配，并生成浅色/深色关键页面截图。若要验收本机已经安装的版本，运行：

```bash
MY_WAY_E2E_EXECUTABLE="/Applications/My Way.app/Contents/MacOS/My Way" npm run test:e2e
```

macOS 全屏用例通过 System Events 向隔离测试进程发送真正的系统快捷键；运行测试的工具需要相应的自动化权限。My Way App 日常使用不需要此权限。

## 打包

```bash
npm run package:mac -- --publish never
```

Apple Silicon DMG 输出到 `release/`。App 使用 ad-hoc 签名，但未经 Apple Developer ID 签名或公证；首次安装后若 macOS 拦截启动，请在“系统设置 → 隐私与安全性”中确认仍要打开。App 不实现自动更新。

## 本地文件

- 周计划：`00-dashboard/weeks/week-NN.md`
- 每日记录：`data/daily/YYYY/YYYY-MM-DD.md`
- 计时状态：`data/timer/state.json`
- 计时台账：`data/timer/YYYY/YYYY-MM-DD.md`
- 路线文件只读：`00-dashboard/12-week-roadmap.md`、`long-term-roadmap.md`、`current-status.md`

所有每日写入均使用同目录临时文件后原子替换，并携带 SHA-256 修订值检测外部修改。个人学习目录请放在源码仓库之外，仅作本机存储或本地备份；不要提交到本仓库。空白工作区与初次启动说明见[仓库 README](../../README.md)。

## 本周计划

左侧“本周”按本机日期识别当前周一至周日，并根据已有 `week-NN.md` 推导路线周次。当前自然周没有计划时，“今天”会保留现有每日记录，并提供“建立本周计划”入口；第一次点击保存后才会创建对应的周计划文件。

- 上次计划只作为参考候选，未完成或跳过的任务不会自动堆到本周；只有明确勾选并点击“加入草案”的项目才会复制。
- 新增、编辑、删除、排序和周说明均先进入本地草案。已有周计划采用短延迟自动保存，首次创建必须明确点击“保存本周计划”。
- 周目标按本周任务卡片自动汇总，不固定为 20 小时；入试、NLP、英语、日语计入学习时间，健身使用独立的计划与实际时间条。
- 周计划保存不会重写已有每日快照。若本周新增了当天任务，“今天”会显示差异，并等待用户点击“导入新增任务”。
- 日历合并周计划与每日任务；在“今天”新建或复制的卡片、计划分钟和完成状态都会显示，无周计划时也可使用，跨月周按完整七天读取。已有周计划任务与每日快照按来源去重，浏览日历不会生成或重写学习文件。
- 日历周视图可在周一至周六之间拖动周计划任务。拖动会携带文件修订值保存周计划；已有每日记录继续作为历史快照保留，保存冲突时画面会回滚并显示原因。独立每日卡片可点击打开原任务详情进行编辑。
- 点击周视图日期或月视图日期可以读取并编辑历史记录；没有记录的日期保持只读空白，只有明确点击“开始记录”才会创建每日文件。
- 打开跨周历史记录时，右栏切换为该日期的“所在周”计划与实际投入；离开历史日页面后恢复当前自然周，避免混用两周数据。
- App 会在主进程检查证据引用。文件缺失或路径不安全时只标记引用，不删除任务或真实文件；可在任务详情中替换路径或仅移除引用。
- 任务状态默认按已入账时间自动显示：0 分钟未开始、大于 0 进行中、达到计划已达标；不需要循环点击状态。也可提前完成或恢复自动。达标只代表时间投入，不代表知识掌握，不会停止计时。
- 前一日未完成任务放在今天底部的折叠“待处理任务”区域，不抢焦点、不自动顺延。明确顺延时只移动剩余预算，原日实际、成果和证据保留；处理期间串行写入并保护当前未保存编辑。新顺延记录通过可选 rescheduledMinutes 保留已消耗预算，旧记录无需迁移。
- “今天”页可新增、编辑与删除过去问记录，保存科目、试卷、日期、得分和满分；记录进入同一份每日 Markdown，并自动汇总到本周复盘。
- 周计划在 App 外发生变化时，干净页面会重新读取；本地仍有修改时会进入冲突状态并保留草案，直到用户明确重新载入。
- “复盘”只从本地每日记录派生实际时长、完成率、方向分配、证据、过去问、任务成果和日终复盘摘要；日期可打开原每日记录，任务成果标题可直达对应任务详情，路线 Markdown 始终只读。

## 任务创建、复制与保存

- “添加一项任务”先填写标题、类别、日期与计划分钟，预期产物和备注可选；确认创建后打开详情。取消不会生成占位卡片。
- 今日/当日卡片和详情中的“复制”可微调后创建独立副本。复制标题、类别、计划分钟、预期产物与备注，不复制实际时长、完成状态、成果、证据或来源 ID。跨日副本写入所选日期的每日文件，不改动原任务。
- 本周计划行也可复制，副本先加入周草案；周计划格式不含任务备注，因此该表单不提供备注输入。
- 计划/实际分钟支持删空后重新填写，分钟标签和输入周围区域不会打开详情。非法输入保留在编辑器并给出提示，修正前不保存、不离页、不关闭；实际分钟空白按零处理。
- 详情中的“保存”立即写入并留在详情，“保存并返回”在写入成功后返回列表。原有自动保存、Cmd+S、修订冲突保护继续生效。未确认的新建/复制表单会阻止关闭，需先创建或取消。

## 学习计时器

左侧“计时器”支持自由计时与 1–180 分钟倒计时。计时开始后可以切换到今天、日历、本周、路线或任务详情；主进程会继续按本机时间结算，不依赖当前页面，也不会每秒写入磁盘。

- 今天的任务详情可直接点击“开始专注”，建立带任务标题、任务 ID 与日期快照的自由计时。该上下文会随活动计时和待分配台账持久化，关闭并重开 App 后仍可识别原任务。
- 已有活动计时时，任务详情只提供“查看计时”，不会创建第二个计时器；历史日期不提供任务绑定启动入口。
- 暂停或结束必须由用户明确操作；倒计时到点会停在准确的结束时刻。
- 关闭 App、电脑睡眠或系统挂起时自动暂停，重新打开后不会把关闭或睡眠时间计入。
- 完成的时段先保存在原结束日期的计时台账中，再由用户分配到该日的任务；跨日期未分配记录会保留在待分配列表。
- 带任务上下文的计时结束后会默认选中仍然存在的原任务，但实际分钟仍须用户确认，也可改选其他任务或暂不分配。
- 分配时可以调整实际计入的整数分钟，App 会同时更新每日 Markdown 与计时台账；任一文件冲突时都不会只写一半。
- App 不发送 macOS 通知，也不会在 App 关闭后后台计时。

若计时文件被外部修改、损坏或产生修订冲突，计时功能会进入只读状态并显示具体文件。请先按提示修复或还原该 `data/timer` 文件，再回到 App 重新载入；其他学习页面仍可继续使用。

## 键盘工作流

- `⌃⌘F`：通过原生“窗口 → 切换全屏”菜单进入或退出全屏；文本编辑和模态窗口中仍可使用。
- `⌘1`—`⌘5`：切换“今天”、“日历”、“本周”、“路线”和“计时器”。
- `⌘S`：立即刷新当前每日记录的自动保存；在“本周”页则立即保存周计划草案。
- `⌘[`：从任务详情返回当日任务列表；若该日由“本周复盘”或日历打开，再按一次返回来源页。

当确认、顺延、计时分配等模态窗口打开时，学习页面快捷键暂时停用，避免绕过当前决策；系统全屏快捷键不受影响。

macOS 全屏时可能自动收起原生标题栏。App 左上角另有“退出全屏”按钮，在首次选择工作区、正常学习页面和错误恢复页都可用；退出全屏不会刷新页面、结束计时或丢弃编辑草稿。

## 界面规范

界面采用三栏学术工作台与单一靛蓝强调色，浅色和深色模式使用相同的信息层级与几何规则。维护渲染层时遵循以下约束：

- 导航保持纯文字，当前页面使用左侧竖线标记，不添加装饰性字母或图形。
- 页面副标题、区块标题、字段标签和简短状态使用名词短语；错误、冲突和删除确认保留完整说明。
- 界面文字统一使用 macOS 系统无衬线字体；计时与定量数据可使用等宽数字。
- 常规控件高度为 34 px、圆角为 6 px；状态点、完成标记和进度环必须先保持正方形，再使用 `border-radius: 50%`。
- 动效只用于按压反馈、偶发弹窗和明确的状态变化，使用共享强 ease-out 曲线并保持在 300 ms 内；主导航、计时数字和学习数据不做装饰性运动。
- 移动动效必须同时提供 `prefers-reduced-motion` 版本，移除位移与缩放但保留短暂的颜色或透明度提示。
- 主导航与路线文档使用 `aria-current`，周/月、计划/复盘、编辑/预览与计时模式使用 `aria-pressed`；自绘进度必须同时暴露数值文本。
- 从任务详情或历史日返回时恢复来源控件与滚动位置；重复操作按钮必须在可访问名称中包含任务或计时记录上下文。
- 普通页面不显示英文 eyebrow、存储实现细节或重复提示；诊断信息只在错误与恢复场景中出现。
